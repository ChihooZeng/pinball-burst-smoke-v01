## 1. 怎么运行

```sh
cd compare/dynamic-field-mg-v2-20261104
python3 -m http.server 4185
```

打开 <http://127.0.0.1:4185/>。无需安装、无需构建。

QA 直达：

```text
http://127.0.0.1:4185/?mode=M2&field=B
http://127.0.0.1:4185/?test=1&mode=M1&field=A
```

- `mode`：`S1`、`C1`、`M1`、`M2`
- `field`：`A`、`B`、`C`
- `test=1` 才暴露 `window.__pinballLabTest`；正常入口不暴露可改状态的接口。

## 2. 菜单与对照

**4 种模式 × 3 种战场 = 12 组**，菜单先选模式再选战场；同一战场下切换模式，砖阵初始结构与生成规则一致。

| 模式 | 内容 |
|---|---|
| S1 砖块开花 | 主炮击碎砖块 → 短寿命子球；子球不再开花 |
| C1 雷花风暴 | S1+S3：开花子球首次命中布微电极，与普通电极连线放电 |
| M1 极速直线机枪 | 0.08s/发，持续直线弹流；真实弹球/碰撞/1 点伤害 |
| M2 极速扇形机枪 | 0.15s/轮，每轮左中右三球；三方向独立碰撞/1 点伤害 |

**巨型球隔离**：S1/C1 保留 V1 的自动巨型球；M1/M2 关闭巨型球，避免大招掩盖射速验证。这是显式实验隔离，不是正式规则。

## 3. 三种战场

| 战场 | 结构 | 生成预算 | 预警 |
|---|---|---|---|
| A 顶部下落 | 仅顶部初始砖阵 + 顶部持续补行，持续下落 | 顶部合计 126 块 | 顶部生成不需要中部预警 |
| B 中部增援 | 顶部下落 + 中部定时 3 块增援 | 顶部 108 + 中部 24 | 每批 1.0s 虚线框 + 进度条 |
| C 中部召唤 | 顶部下落 + 中部召唤核心；核心存活时召唤 | 顶部 108 + 召唤 24 + 核心 1 | 每批 1.1s；击破核心立即停止剩余召唤预算 |

- 中部生成 y 至少离危险线 **120px**（`minDangerGap`），不会直接在危险线附近出现。
- 预警期间占位，不允许其他砖块生成到同一格；预警结束才落成实体砖。
- 顶部/中部预算有限；预算耗尽且砖块清空后，本局**必然可以清屏**。
- 初始 A 最多 12 排、B/C 9 排；按安全区动态裁切，避免刘海屏压住 HUD。
- 下落速度 A 5.4、B/C 5.2 px/s，并随时间轻微加速。

## 4. 两种机枪的硬参数

| 项 | M1 | M2 |
|---|---|---|
| 触发间隔 | 0.08s（12.5 次/s） | 0.15s（6.67 轮/s） |
| 每轮弹数 | 1 | 3（左/中/右，±0.12 rad） |
| 弹球寿命 | 3.0s | 1.8s |
| 理论在场上限 | 37.5 | 36 |
| 同屏硬上限 | 48 | 48 |
| 伤害 | 1（真实伤害） | 1（真实伤害） |
| 达到上限 | 移除最老机枪球继续射击 | 移除最老机枪球继续射击 |
| 充能/爆发 | 无，持续自动 | 无，持续自动 |

实测（10 秒固定瞄准）：

- M1：**12.5–12.54 触发/s**，峰值 **38 球**。
- M2：**6.66–6.69 轮/s**，**19.98–20.07 球/s**，峰值 **39 球**。
- 两者都没有“打一轮等很久”的爆发冷却；达到 48 上限时回收最老球，不停止射击。

## 7. 已知问题

1. **无真机验证**：iOS Safari 实际刘海/灵动岛 inset、地址栏收放、Android 返回手势、真机 60/120FPS、音频与振动均未测。
2. **M1/M2 关闭巨型球**：为隔离射速变量；若正式版要求机枪也接巨型球，需要另做一轮。
3. **B 的清屏时间受生成节奏限制**（约 29–30s）：高射速下会有一段“等中部批次”的体感，需要真人判断是否把 B 的批次间隔再缩短。
4. **C 的召唤核心**若过早被击破，剩余预算会立即关闭；这是有意设计，但可能让 C 比 B 更快结束。
5. **A 的下半屏仍比 B/C 空**：A 的定位就是纯顶部供给；如要更满，应调初始排数/下落速度，不要偷偷加中部生成。
6. M1/M2 的真实手感（12.5/s 与 20 球/s）只经过自动样本；是否“爽”、是否过密、是否晃眼需真人试玩。
7. 没有 Boss、45 关、正式成长树或存档；本轮不做。
