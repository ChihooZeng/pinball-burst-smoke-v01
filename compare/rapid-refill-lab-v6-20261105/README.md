## 1. 一句话

每击碎一块砖，系统立刻欠下 2–3 块新砖；只要有安全位置，0.3 秒内就补进战场。
不设批次冷却、不设"击碎 N 块才补一批"，战场默认保持高密度。

## 4. 极速补砖机制

| 项 | 值 |
|---|---|
| 初始砖块 | 72 |
| 触发 | 每击碎 1 块，债务 +2~3 |
| 批次冷却 | **无** |
| 生成节奏 | 债务 >0 且 `elapsed >= next` 就补，`next = now + 0.06s`（合帧，不卡） |
| 单轮上限 | 6 块 |
| 总预算 | 180 块 |
| 存活上限 | 90 |
| 预警 | 0.24 秒 |
| 位置不足 | 进队列，0.18 秒后重试；不硬塞、不重叠 |
| 危险线距离 | ≥120px |
| 清屏 | 预算耗尽且真实砖块清零 → 过关 |

生成位置：8 列轮转（`0,3,6,1,4,7,2,5`），行列按序号步进，形成左右侧翼与中部砖簇；
`labCanBatchPlace` 保证不重叠、单行占用 ≥7 即放弃（保留弹球通道）、距危险线 ≥120px。
**不是原地复活**：每块砖都是新坐标、新 HP、先预警再落地。

读法：

- **R1 的中下密度是 C 的 2–4 倍**（S1 12.7 vs 2.7；M1 11.1 vs 5.2；S8 5.9 vs 0.3）。
- **R1 全部技能空档 ≤1.64 秒**，满足"不超过 3 秒"的要求；C 在 S1 下也有 3.05 秒。
- **R2 的分裂很明显**：M1 还能维持 2.07 秒空档（高射速啃高 HP），S1 掉到 11.84 秒——
  低 DPS 技能面对 20–40 HP 砖块，8 秒内可能一块都打不碎。这是真实结果，没有偷偷加伤害。

## 7. 已知问题

1. **180 预算烧得很快**：S8 在 15 秒内打光，M1/S1 约 20–30 秒。之后靠存量砖块收尾。
   要做更长的关卡，需要把预算提到 400+ 或按关卡分段给。
2. **R2 的低 DPS 体验很差**：S1 打 20–40 HP 砖块，首批破碎要 8 秒以上；这是刻意保留的对照结果。
3. **存活上限 90 会挡住补砖**：R2 经常顶在 86–90，补砖请求进入延迟队列（30 秒内 103–123 次延迟）。
   上限本身工作正常，但高 HP 下"补不进去"会很常见。
4. **中部偏空**：8 列轮转仍偏侧翼，画面中央常留一条宽通道；可把列权重往中间调。
5. **自动转火是模拟**：指标按"砖最密处"瞄准，不是真人。
6. **未做真机、未做真人**：FPS 与手感均为 headless 推断。
7. 未做 45 关、成长树、存档、Boss；未改技能数值。
