# 弹珠超载 v0.20 — 密集砖潮与帧率优化

基于 v0.19 独立复制的试玩版，继续以 **v0.17 的单炮台、弹球反弹、技能连锁及视觉音效**为核心，不使用 v0.18 四职业方案。v0.17/v0.19 原版未修改。

## 此轮反馈与改动

| 项目 | v0.19 | v0.20 候选 |
|---|---|---|
| 初始数量 | 3 行、每行约 6 块（18 块） | 6 行 × 9 列（54 块） |
| 下降速度 | 初始 5.1 px/s | 初始 8.8 px/s，随生存时间升至最大约 16.4 px/s |
| 普通补砖 | 初始约每 5.7 秒一排 | 初始约每 4.1 秒一排，后期加速 |
| 砖潮 | 定时加强 | 保留，缩短砖潮补砖间隔 |
| 初始球速 | 365 px/s | 292 px/s（降低约 20%） |
| 初始发射间隔 | 0.86s | 1.04s（较慢） |
| 初始装甲伤害 | 2 | 1；随火力升级提高 |
| 首次升级经验 | 12 | 6；保留前期较弱但不能死于首次升级前 |
| 图形与物理更新 | 每 rAF 计算 variable dt，单球至少 4 个物理微步 | 以 1/120 秒固定物理步长；每帧渲染取决于设备浏览器 rAF（不硬编码 60/120） |
| 每帧 DOM 更新 | 每次模拟调用 updateUI | 平时约 10Hz UI 更新；升级/触控等事件仍立即更新 |
| 碰撞检测 | 每球每次微步遍历全部历史砖 | AABB 快速排除 + 每半秒清理已死亡砖，不让死砖堆积 |
| 画质回退 | 强反馈常开 | 实际低帧率时自动减弱砖块阴影（不是减掉弹球物理） |

**修正 Boss 与密集砖阵兼容性：** Boss 支援位置若已有普通数字砖，转化附近砖为 Boss 支援砖，而不是生成一个重叠砖；Boss 本体范围排除重叠普通砖，避免双重碰撞和视觉遮挡。

## 帧率说明

- 物理模拟统一 120Hz 固定步长；以 rAF 驱动渲染，在支持高刷新率的浏览器/硬件上**可以**按 60Hz / 90Hz / 120Hz 回调，无法强制浏览器给予 120 FPS。
- 手机顶部显示实测 FPS（短时间平均），不是设置目标值或宣传数。
- 自动化脚本模拟 60Hz 和 120Hz rAF，10 秒游戏逻辑时间分别为 9.99s 和 10.00s，证明不会因高刷新率加速游戏。
- Windows Edge Headless CDP 测试环境在**静止启动画面、实战、关闭特效**三个状态都是约 **30 FPS**，证明该无头环境限制不能作为实际 iPhone / 高刷显示器可达帧率的证据；真实 60/120 需用户设备验证，不能宣称已经达到。

## 验证

- `cd compare && node v20-denseflow-test.js` PASS：54 块起始密度、低起始射速/球速、60/120Hz 模拟、经验升级暂停、Boss 召唤砖与击败奖励、触线失败、清屏经验奖励冷却。
- 250s 自动瞄准回归：514 击碎、LV12、14 次技能选择、3 次 Boss、29 次清屏，仍存活；第一次选择约17.4s，首次清屏约24.1s，第一 Boss 在78s。**这不是人类试玩平衡结论**。
- `node v20-mobile-cdp-qa.js` PASS：390×844、375×667、320×568 全页可见、无横竖滚动、无 JS 错误、真实手势启用 AudioContext；帧率诊断见上。
- `node v17-sustain-test.js` 原基准回归通过。
