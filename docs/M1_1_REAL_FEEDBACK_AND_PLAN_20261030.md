# 《弹珠超载》M1.1｜真人手感反馈、单体战斗与手机沉浸化修复任务（2026-10-30）
> 性质：已确认产品目标 + 待实验实施建议，**本次只归档，未实施或验收**。
> 最新基准：`codex/v1-m1-soft-balance` / `compare/hybrid-v1-m1-soft-balance/`；完整50波目标始终不变，M1只是1–10波测试。
> 用户真实iPhone内置浏览器截图：第7波、清理73/78。剩余5砖，存在数字15、19、9等高耐久目标，零星球在空场往复，继续清除乏味。

## A. 明确确认 / 仍待决定

**已确认：** 调弱版基础伤害1、基础飞行速度330作为后续开发战斗基线；问题焦点是群伤充足却单体不足、Boss磨血；游戏应占据手机可用画面，设置入口右上角，去掉内框；砖块下降略加快。
**仍待实验：** 尾砖判定阈值、集火/破甲具体数值、Boss新阶段或弱点的HP与触发、下降`fallScale`具体值、HUD精确坐标与交互。不能把这些方案写成用户已批准的精确数值。

## B. 已核对代码事实与可能成因

- `builds.js` 当前`baseDamage:1`、`speed:330`、`fallScale:.8`；普通发射间隔`.86`，机枪R1`.35`。
- `game.js` 为真实碰撞物理。单体输出不因场上目标少而自动有效增强；电弧仅有少量孤立回退，既有M1报告弱电弧第7波失败。
- `generateSurvival` 原型仅`live.length<=3 && waveElapsed>12 && !boss`时将部分剩余砖软化至3HP；第7波73/78仍有5砖，永远不符合该触发。Boss遭排除，后期单体磨血。
- `style.css` 的`.shell` 最大宽440px、上下固定HUD/控件占高，`.arena` 为360:560固定比例、圆角边框、阴影；屏幕看上去“网页内嵌小游戏”，浏览器工具栏进一步缩小实际画面。
- 当前下降物理速度`min(8.4,6.8+(wave-1)*.09)*bossFactor*.8`；第7波非Boss约5.87逻辑px/s，`.86`将约6.31px/s（约+7.5%）。此为方案而非确认数值。

## C. 研发方案与优先级

### P0-1 破除尾砖/Boss单体坐牢
1. **优先技能成长修复**：同一个强主核心必须有明确可升级的单体能力。裂变主：少目标时优先有限追猎/集中子球；电弧主：没有足够传播对象时，合格充能转为有限单体放电；机枪主：连续有效直接命中同一目标获得层进破甲。三条路线既保持各自身份，也均能应对高耐久Boss。
2. **基础残局保障**：进入残砖阶段（先AB试剩≤5或其他阈值）为真实弹球提供低强度目标引导/反弹导流；不可伪造远程秒杀或自动清屏。不能要求抽到罕见技能才能结束普通波。可以显示“残局追击”反馈，保持打碎最后一砖的成就。
3. **Boss设计**：阶段弱点、有限护卫或攻击窗口；不要仅提高基础伤害或强制无限刷护卫。Boss核心孤立时必须存在技能可兑现的攻击机会，而非靠巨型球耗血。
4. 评估现有`tailSoftens`隐式HP减至3是否保留：优先透明、可感知、通过命中实现的补救，而非不可解释的数字魔术。
5. 改进升级卡池：每局确保某些普通高耐久对策可获取，且玩家能够看懂“对单体破甲/定向能力+X”的实际收益；不要在所有流派里发同一张超强万能卡。
6. 对比：原调弱版 vs 单体能力版。固定seed、弱Build、三纯流派、混合路线、残5砖/3砖/1砖、孤立52HP Boss、4/8波Boss，以及不使用巨球；记录尾砖耗时、最长无击碎、命中率、Boss时长、全波清屏时长与反馈。

### P0-2 移动端满屏沉浸化
1. 只把**可用Web视口**铺满，浏览器顶部/底部自身工具栏不能由网页强制隐藏；可提供PWA主屏独立模式作为后续可选提升。
2. 将`.shell`由独立卡片容器改为沉浸式游戏布局；移除`.arena`边框、圆角和大片外边距；战斗区域尽量最大；必要状态HUD用轻量叠加，不挤压游戏世界。
3. 右上角**设置菜单**：音量、画质、暂停/Build、成长记录、导出、重新开始。游戏画面常驻重要项目：波数、清屏进度、必要Buff和Boss血条、警戒线、超载按钮。设置菜单需触控友好、可访问、可在暂停/恢复间正确冻结时间。
4. **真正响应式物理世界/相机**：canvas显示比例与世界坐标适配不同长宽比，砖大小/球速/警戒线/碰撞一致；不要把360×560画面简单`scaleX/scaleY`拉伸，或裁掉炮台/危险线。兼容safe-area、动态浏览器栏、方向变化、键盘导航，适配320×568、375×667、390×844与宽屏。
5. screenshot baseline：用户截图中游戏面板有内框、外围文字HUD冗余，上下浏览器栏遮挡；新版至少能显著扩大有效场地并消除内容被浏览器控件覆盖的主要问题。

### P1-3 下落略增紧迫感
- 初轮只做对照：`fallScale .80→.86`（约+7.5%），保留其他速度公式；也可测试`.84`。不可把示例参数当最终审批。
- 首先修复孤砖/Boss磨血后，再测试下降速度与弱电弧平衡；记录清屏时间、触线率、难度突增波、玩家真实体感。
- 不可因压力增加导致玩家在第4波前没有足够构筑机会或只剩Boss时无解。
