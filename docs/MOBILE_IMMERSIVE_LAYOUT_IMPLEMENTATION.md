## 布局与坐标

| 部位 | V2.1 | 方案 C |
| --- | --- | --- |
| 背景与边界 | 战斗表面有独立网格与四边矩形 | 页根铺设一张网格，移除独立表面与矩形。Canvas 在物理左墙、右墙、顶墙画低亮度提示，侧轨向底部淡出 |
| 手机 HUD | 单独的标题行、绝对定位 HUD 和血条 | 取消重复标题占位，HUD、Boss 血条、战斗区和技能栏分占 Grid 行 |
| 技能栏 | 独立实色装饰层 | 透出网格的底部技能区，保留及实测核对主要按钮 44 CSS px 热区，提示文字按行取空间 |
| 桌面 | 居中的战斗场地 | 保留左右位置、尺度和鼠标操作。Boss 血条出现时让出场地顶部 16 CSS px，使用原有底部余量 |

`fitCanvas()` 从实际场地槽取可用尺寸，按同一尺度居中适配整局世界，读取最终 Canvas 矩形得到唯一的 `fieldTransform`。屏幕坐标等于矩形原点加逻辑坐标乘尺度。触摸用同一对象去掉原点、除以尺度。DPR 最多取 2，只影响取整后的后备像素。Canvas 绘制补偿后备像素取整，页面上保持横纵等比。砖块、球、炮台、瞄准线、警戒线和墙面提示均使用这次变换。普通球从底部离场；超载巨球使用原有反弹面。

开局逻辑 H 仍使用 V2.1 的槽尺寸计算规则。CSS 隐形几何参考只负责维持基线测量，当前可见布局由实际占位决定。66 组额外的视口与安全区组合中，两版开局 H 无差异。窗口变化时，现有 `ResizeObserver` 和 `resize` 更新显示变换并释放指针，当前局 H、砖块和球体状态继续沿用。Chromium 的缩高、横竖屏和页面捏合模拟通过，保留浏览器原生坐标行为。镜头震动作用于冲击和胜利特效；场地边缘、警戒线、砖阵、球和炮台锚点保持坐标稳定。

## 验收

- **显示与触摸。** 检查场地四角、警戒线和炮台枢轴的正反映射，几何断言容差为 0.08 CSS px，目标要求小于 1 CSS px。三种手机视口发送 Chromium 原生触摸，检查炮管角度、跨墙拖动、`touchCancel` 后的新手势、缩高和 1.1 倍页面缩放。捕获 Canvas 实际笔画，确认顶墙为 y=4，左右为 x=0、360，底部开放，冲击震动前后边界笔画不动。
- **物理和数值。** 四个视口共 80 组开场砖阵，固定种子的砖位置、尺寸、HP、下落速度和倍率逐项相等。原尺寸 29×22，横缝 9.5、纵缝 9，普通球碰撞半径 2.7。实测两向穿缝、三面反弹、普通球底部离场、巨球反弹、炮口位置、警戒线判负、Boss 预警及实体增援、终局阶段和 48 球。另对比 39 场 V2.1 种子回归的完整输出，逐项相同。Git 逐字节检查游戏保护函数、构筑、语言、音效、炮台素材、隐私、统计和服务。
- **真实输入通关。** 裂变 360×640、电弧 390×844、机枪 430×932 使用触摸，桌面 1440×900 使用鼠标。四局均完成 20 波、达 5 级、击败两名 Boss、经过终局 1/2/3 阶段，控制台错误均为 0。桌面真实通关后，再用最终布局核对 Boss 血条间距和场地尺寸。
- **界面。** 检查中文、英文、升级选卡及防误触、暂停、恢复、重开、胜利、失败结算与资源。后台返回通过模拟 `visibilitychange`，复验时钟暂停和恢复。静态发行入口还检查隐私页和 BGM。
- **音频与振动。** 10 个有效音效和 BGM 首触、音量、静音与恢复通过。原四个静音事件全为零播放和零加载。以 Chromium API 探针验证关闭振动时零调用、开启后击碎普通砖调用 16ms。物理设备振感未测。
- **性能与服务。** 本机 Chromium 密集波及 Boss 采样约 59.4–59.9 FPS，P95 帧间隔 16.7–16.8ms，样本内无 50ms 长帧。十次重开后的 JS 堆未增长，模拟绘制错误的恢复流程通过。独立本地统计服务的同意、撤回、事件和私密后台测试通过。
- **实机范围。** Chromium 模拟覆盖地址栏收缩对应的 80px 高度变化、浏览器缩放、定制安全区和横竖屏。实体 iOS Safari、Android Chrome 和微信内置浏览器本轮未接入。
