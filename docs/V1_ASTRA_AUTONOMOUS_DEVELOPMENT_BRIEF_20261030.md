## 1. 已确认的产品宪章（不能因为自动模拟好看而改变）

- 同一炮台发射**真实反弹弹球**。核心爽感：连续接触、明显掉 HP、碎砖、清屏、组合连锁；“约70%破坏爽感/30%Build与挑战”为定性方向，不是硬性算法比值。
- 一局最多挑战 50 波，Build 跨波不断成长。标准波整波生成砖阵并缓慢下降，**普通波中途不持续补砖**；全部实体砖包括 Boss 真清屏才结算下一波。
- 每完成一波，默认一次三选一**永久成长**；清除场上的普通球、子球及巨型球，但**不清除永久Build和未到期临时Buff**。选择/暂停/过场均暂停有效战斗计时。
- Boss约每4波一个，有限召唤；**额外 Boss 奖励尚未确认**，不能把它当作已经获批的额外永久卡。
- 特殊砖只能产生即时或15/30秒的**战斗内临时Buff**，允许跨波保留，停止/选择/过场时停表；**绝不掉永久升级、碎片、进化资源或免费抽卡**。
- 三个首批明确的核心流派：裂变（场内弹球增殖）、电弧（目标间传播）、机枪（炮台连续发射），各有独立打法及互斥专精分支；允许副核心弱辅助，不把起始选择变成不可更换的职业。
- 玩家最新真人反馈：v0.27a 过慢、磨人；**Feel Lab B 明显更爽，优先作为下一轮基础战斗节奏参考**；C/D 额外连锁更爽却有前期过强风险，C 与 D 体感差别不大。B 同时调整射速、球速、伤害、机枪 TTL、首发，不得错误归因为“仅射速”。将 C 的超强连锁留作中后期增量候选，不直接全量移植到第1波。
- 升级卡只突出**玩家实际获得的增量**，比如“炮台射速 +10%”“分裂额外 +1 颗”“闪电额外命中 +1 目标”；不要显示毫秒、内部冷却等工程参数。**升级前后差异、真实总属性、技能树、Build历史放入暂停菜单**。展示值须与实际有效属性计算匹配，不能对已封顶或被覆盖的效果虚报增量。
- 难点在持续提升破坏行为，而非每波增 HP；尾砖难打、孤立 Boss 空场、弱构筑卡死、32 球限制、移动端发热/掉帧都属于核心问题。
- 不因为加技能而加技能；避免无限递归链、隐藏回收射击、球池饱和、特效遮挡数字砖。保留旧版对照、保留独立试玩入口，不未经许可替换默认线上版。
- 稀有/史诗/传说应提供惊喜与稀缺；**常规完整Build不能依赖抽中传说**。品质/功能/进化三者是独立轴，不自动捆绑。

## 2. 本次新增授权：**开放技能研究**，四类只是起点，不是封闭分类

过去“基础/核心/辅助/专精”只是方便起步的 UI/策划视角，**不得作为技能扩展数量上限或代码硬编码枚举**。Astra 获授权主动研究已有优秀游戏/开源工程中的技能机制，并提出新的玩法家族、触发机制、联动机制和特殊进化。

采用多维技能模型：
- **功能/战斗位置（可多标签）**：炮台、弹道、碰撞、破碎、状态、范围传播、目标控制、反弹、主动能量、回收/防守、进化、协同、条件增幅等，可扩展。
- **事件触发**：on_fire、on_wall_hit、on_brick_hit、on_break、on_chain、on_energy_ready、on_boss_phase、on_wave_start/end、on_timer 等，必须限制由间接事件再次递归触发。
- **效果本体**：增量属性、发射数量、改变轨迹、改变碰撞性质、生成有限子球、传播伤害、标记目标、专注打Boss、清理尾砖、短时爆发等。
- **成长地位**：普通卡、流派核心、跨流派联动、条件突破、被动模块、主动技能、神器候选、正常专精进化，允许交叉但 UI 要可解释。
- **稀有度**：普通/稀有/史诗/传说（后续可扩展），与功能类别和进化阶段分离。
- **边界字段**：前置、互斥、上限、预算、触发冷却、单次/每波最大触发、Boss孤立目标的回退行为、数值单位、卡面增量表达、仪表盘真实属性来源。

优先在现有数据驱动模型上升级，不提前预设技能总数为15、20或某个封闭值。Astra 可提出新机制，但**不能在未经对照验证时把研究到的全部技能一次投入三选一卡池**。

## 3. Astra 的技能发现与筛选流水线（持续贯穿开发）

### R0｜先检索、再创作
- 先研究至少 6 款相关游戏的技能成长、混合、稀有与选择体验（优先 BALL x PIT、Nova Drift、Brotato、20 Minutes Till Dawn、Vampire Survivors、Noita；必要时补充弹球/打砖块游戏）。
- 官方开发者资料与可核查的游戏机制优先；社区Wiki/用户攻略标记证据等级。若发现成熟开源实现，检查许可证与适配成本；**只借鉴机制逻辑，不照抄专有名称、文案、图标、角色、美术、代码**。
- 建立至少 24 个“机制模式卡片”（不是 24 个已批准投产技能），记录游戏来源、原玩法、适配思路、适用流派、视觉爽感、性能风险、版权/实现成本。
- 将候选纳入 docs/V1_SKILL_RESEARCH_LIBRARY.md（执行时新建并持续维护，附来源 URL 和检索日期）。

### R1｜评分与去重
每条候选按六项评估（每项 1–5，权重可调整并写理由）：即时爽感、成长空间、流派差异、玩家可理解性、物理碰撞适配性、手机性能/实现成本；标注是否只是“更高数值”的换皮，是否侵蚀已有三流派特色。对同质效果合并，优先保留清晰、能让画面变化的机制。

### R2｜小规模进入游戏
- 先在 M1 验证**极少量**有代表性的新机制，M2 再加入跨流派联动，M3 扩到高阶稀有/极限能力；**以可验证质量决定每批数量，不设必须实现24项的 KPI**。
- 每个新机制必须有两层验收：独立技能效果可复现；加入卡池后确实带来不同Build，且没有压垮现有普通三选一成长。
- 对每个被否决技能保留原因，不反复讨论被证明无效的方案；有新证据可以重审。
- 每完成一个里程碑重新检索/审查候选库，把“寻找好技能”变成开发常规流程，而非一次性脑暴。

### R3｜实测淘汰
- 不产生有意义的破坏变化、只能让数值膨胀、卡面难解释、严重克制/碾压单一流派、需要无限产球、手机帧率不可接受或制造无聊收尾时，应削弱、合并、撤销。
- 抽到稀有技能不应导致“Build 无法成型”；无稀有路线依然能玩、能过关键关。
- 精确展示：数值属性建议写百分比**有效增量**；实体数、命中目标数、穿透次数仍用整数；暂停面板显示升前/升后及累计值。

## 4. 50 波成长经济与玩法阶段（设计假设，由 Astra 细化并验证）

- 若通关 50 波就结束，**进入下一波前可对战斗生效的常规波末强化最多 49 次**（结局后升级不可计算作第50波战力）。开局 seed 不应计入这49次；Boss奖励等额外来源须经明确批准后才计入。
- **1–10**：采用B底盘，弱而可见的首发流派特色，较少强连锁，首次专精/联动候选。
- **11–20**：主核心成熟，出现可预期的进化，初步跨流派联动，群怪/孤立Boss表现均可接受。
- **21–35**：高阶专精、有限稀有/史诗、不同阵型克制与反克制，避免累计升级提前封顶。
- **36–50**：顶级突破、少量真正稀缺的传说/超限机制、渐进Boss变化，但不靠无限HP拖延；必须仍有成长选项。
- 开局选一个主要方向不代表把副核心封死；一个**强主核心 + 有限弱副核心 + 辅助联动**，避免三条流派最终变同一个全能 Build。
- 普通三选一采用“方向/稳定/探索”引导式随机；未解锁/满级/无效/互斥卡不可出现；控制玩家长期拿不到主流派升级。稀有可有惊喜，常规专精有阶段保底；不得不披露的概率/配方不要伪装成绝对保证。
- 要求 Astra 交付明确的 50 波**可选卡数量预算**、技能等级上限、卡池轮换策略、普通/强/弱 Build 的可达路线及后期的候补选择，以免第 28 波卡池枯竭。
- 时间目标不是把 50 波硬压进旧文档的 10–15 分钟；**单局时长、分段中断/续玩需求须通过真实测试再定义**。

## 5. 技术设计方向（可自主选择实现方案）

- 数据驱动 Skill Definition + Trigger Pipeline + Effect Resolver + BudgetGuard；状态/条件与数值可查看、有测试覆盖。先利用已有体系，再重构，不为了架构炫技写大工程。
- 全局触发图应可检测环/反复递归，间接撞击/电弧/分裂不得隐式无上限生成伤害。优先保证真实物理的触发与可见性。
- 32球为当前参考上限，**不是永久产品上限**；先采集峰值占用、回收计数、未成功发射/触发次数与手机帧率，再决定提高预算、合并视觉球、TTL调参或其他优化。禁止显示“分裂+1颗”但因预算长期未生成。
- 按 120Hz 固定物理步进、浏览器FPS和移动端真实条件验收；模拟帧一致不代表真机60FPS稳定。
- 技能卡文案由数据计算生成，不允许手写过时数值。拥有较高等级且实际边际收益下降时，要展示**实际**提升值；叠加规则在暂停Build明细可查。
- Boss孤立核心、末尾1–3个残砖、低射速开局和弱升级路线必须进入独立场景。
- 严格隔离开发、测试和发布；每个试玩里程碑独立目录/版本，保留历史对照，默认首页与旧分支不自动替换。

## 6. 开发任务与 Gate

### Gate 0 — 在编码前冻结“规格与预算”
交付：50波成长地图、技能触发数据模型、主副核心约束、真实三选一预算、Skill Research Library 首批≥24机制模式（仅研究，不代表全部实施）、卡牌与暂停面板信息设计、风险与回退计划。
允许 Astra 自主提交**有比较依据的建议**；**尚无用户批准的Boss额外奖励、稀有率或40个新技能数量等不能写成已确认**。

### M1 — 1–10波真正好玩
在独立开发分支恢复 B 版爽感底盘；保留三大方向差异，不直接移植 C/D 初期全爆发。落实“选择卡增量/暂停面板总量与升级前后”；用逐波性能和破坏频率验证，制作真实手机可玩的独立试玩版。自动测试通过只是候选，**真人 Gate** 决定是否推进大规模后期扩充。

### M2 — 11–20波完整Build
分支/专精正常成熟、至少若干有意义的跨技能协同、Boss单体与残砖体验改善；不能因为没抽到传说无法成型。升级数值、卡池公平性、长期累积平衡真实可测；新增机制须由研究库评分后纳入。

### M3 — 21–50波完整挑战
构筑再进化、少量稀有/史诗/传说作为惊喜、复用的阵型族和Boss行为差异；完成三核心/混合/弱势/极限路线的50波仿真，至少在手机上完成真实长局验收，排查性能及停/续玩。只升砖HP而没有新行为视为失败。

### M4 — 可公测质量
新手引导、玩法理解、技能卡、暂停/恢复、存档与异常、触控/音频、结算与重开、H5兼容性、iPhone Safari和Android Chrome、无障碍基本检查、性能与长局稳定性；发布准备及说明。**没有获得用户人工 Gate 就不能把原型描述成完成、不能自动部署正式默认入口。**

## 7. Astra 的决策权限

**可自主**：检索技能与成熟代码、设计数据模型、写候选文档、在独立分支实现和反复自测、修复Bug、做代码审查与性能优化；逐阶段提出候选，并删去被实测证明低价值的机制。

**须报告/对照试验**：大幅调整B底盘、伤害/球池预算、Buff计时、技能卡池规则、稀有概率、额外Boss奖励、20–50波新的压力机制；所有改变需记录基线/假设/可复测证据/权衡。

**必须用户批准**：改变单炮台真物理/真清屏/波末三选一/50波Build连续性、把特殊砖改成永久奖励、强制重置Build、删除或覆盖旧版、从实验目录切到默认线上发布、接入支付广告或对玩家数据做新增收集。

**禁止**：让 Astra 在没有前置条件、评价指标和代码审查时无止境堆技能；仅凭自动脚本的通关结果声称体验好玩；强制使用需付费/版权不清楚的第三方素材代码。

## 8. Astra 的交付格式

每个里程碑应留下：
1. docs/ 下可读的开发决策/研究来源/技能库版本与更改缘由；
2. 明确版本、独立 GitHub 试玩链接、提交 SHA、变更清单；
3. 自动/浏览器/真机的覆盖范围和真实结果（未测试的直接标“未验证”）；
4. 至少三主流派+混合流派+弱路线的回放参数、波次耗时、有效技能收益、触发次数、Boss/尾砖耗时、球池压力和移动性能；
5. 新增技能保留/淘汰原因；面向用户的人话升级卡与暂停Build明细；
6. 下一阶段的风险、需用户批准的产品选择项；禁止以“已完全成熟”掩盖真人 Gate 未做。

## 9. Astra 的起始执行顺序（直接使用）

**第一步只做 Gate 0 和 M1 提案**，不用再请用户重复已确认的50波、B底盘、三流派或UI原则：
- 读取以上资料及当前代码，辨识已实现/未实现、列出冲突和风险。
- 研究相关成熟游戏与开源机制，建≥24候选机制库并筛到首批少量可验证技能。
- 给出50波成长预算及早/中/后期变强与稀有机制分布，量化“普通Build可靠成型，高阶稀有真正稀缺”。
- 设计 M1 可执行任务单、自动验收和3次主要真人手感Gate。
- 审查通过后才在独立分支编码 M1；保持持续自测，保留旧版和回退入口。
