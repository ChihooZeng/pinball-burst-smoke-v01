## 12. 商业化与发行技术准备

### 12.1 当前代码已具备

| 能力 | 现状 |
|---|---|
| 生命周期锚点 | `begin()`(537)、`finishPrototype()`(38)、触线失败(1424)、`chooseUpgrade()`(1089)、`pause/resume`(1925/1930)、`#again`(1975) |

| 数据导出 | 设置面板"下载本局记录"导出完整 JSON（state + events + config） |
| 暂停基建 | `phase="paused"` + `lockBackground()` + `pausedFrom`，可安全承载插屏与激励回调 |
| 接入形态 | 4 个 `<script defer>`，无打包器，广告 SDK 可直接 `<script>` 引入，不需改构建 |

### 12.2 需要补充

1. **广告适配层**：新增 `window.AdBridge = { isReady(), showRewarded(cb), showInterstitial(), onError() }`，默认空实现（no-op），游戏侧只调接口不碰 SDK。
2. **激励场景**：当前**没有复活玩法**（`phase="lost"` 后只能重开），要接"看广告复活"必须先设计复活规则（清危险砖/重置充能/3 秒无敌），属玩法新增 → 本轮不做，作为发行后需求。
3. **插屏时机**：建议只在 `finishPrototype()`（RUN COMPLETE）与 `#again` 点击后、`reset()` 之前触发；**禁止**在 `phase="playing"/"choosing"` 与暂停态触发。
4. **频控**：localStorage 记录 `runsSinceAd/lastAdAt`，建议 ≥2 局或 ≥180s 才允许插屏；激励视频仅用户主动点击。
5. **失败兜底**：`show()` 需带超时（建议 8s）+ 失败静默降级；回调只发一次（防重复发奖）。
6. **埋点**：复用 `record()` 增补 `ad_request/ad_show/ad_complete/ad_fail/ad_skip`，随 `exportRun` 一并导出；上线后接上报通道。
7. **平台适配**：见 12.4。

### 12.3 各平台所需 SDK / 接口

| 平台 | 广告 SDK / 接口 | 承载方式 | 主要改造 |
|---|---|---|---|
| H5（浏览器） | 穿山甲 H5 / 腾讯优量汇 H5 / AdSense | 直接跑 `demo/v1` | 仅接 `<script>` + `AdBridge` 实现 |
| 微信小程序 | `wx.createRewardedVideoAd` / `wx.createInterstitialAd` | **`web-view` 组件套现有 H5**（最省） | 域名白名单、支付/分享能力受限 |
| 微信小游戏 | 同上（`wx.*`） | 需 `wx.createCanvas()` + 无 DOM | **UI 层需重写**（当前 144 个 DOM 元素、71 处 `$("id")`、25 个监听） |
| 抖音小游戏 | `tt.createRewardedVideoAd` / `tt.createInterstitialAd` | 同上 | 同微信小游戏，API 形状接近，可共用抽象 |
| TapTap | H5 走网页联盟；APK 走穿山甲/优量汇原生 SDK | H5 或原生壳 | 原生壳需 WebView + SDK 桥 |

技术事实：渲染为 Canvas 2D（`getContext("2d")`），音频为 WebAudio + `HTMLAudioElement`，**无 WebGL 依赖**——渲染层移植成本低；成本集中在 DOM UI 与输入（pointer 事件 → touch）。

### 12.4 可共用部分

- 游戏逻辑（`game.js` / `builds.js` / `juice-fx.js`）与渲染代码可原样复用（Canvas 2D API 在小游戏环境同名可用）。
- `AdBridge` 抽象层：一套接口，三套实现（H5 / 微信系 / 抖音）。
- 埋点与频控：平台无关，直接共用。
- 音频：WebAudio 在微信/抖音小游戏需替换为 `wx.createWebAudioContext()` / `tt.createWebAudioContext()`，接口形状一致。

### 12.5 推荐的最低成本接入方案

1. **首发只做 H5**：`AdBridge` + 一家 H5 联盟（穿山甲 H5 优先），只在 RUN COMPLETE / RUN OVER 两个点接插屏，激励视频先不做（无复活玩法）。
2. **小程序渠道用 `web-view` 包一层**：零 UI 重写，用小程序原生激励视频组件做外挂奖励（需与 H5 通过 URL 参数/`postMessage` 通信）。
3. **小游戏渠道暂缓**：需要 UI 层重写（DOM → Canvas UI），成本最高，建议在 H5 数据验证后再投入。
4. 三条渠道共用 `AdBridge` 接口与埋点，不为广告改动核心游戏循环。
