## 0. 一页结论（后续开发必须先读）

《弹珠超载》的玩法方向现阶段已经基本定型：**单炮台发射可反弹的物理弹球，以高密度砖阵、连续碰撞、数字耐久不断减少、技能联锁破坏和真正清屏为核心爽感**。玩家在同一局内生存，整波砖阵缓慢下降；**清空全部砖块后才进入下一波**。v0.26 将成长调整为**每完成一波升一级，并且只进行一次三选一技能选择**，清屏时移除上一波所有在场弹球与巨型球。

游戏的美术和 UI 暂以现有**深蓝霓虹、彩色数字砖、清晰 HUD、移动端单屏、弹球发光碰撞反馈**为视觉基准，下一阶段不做全面换肤。关注点从基础循环转移到：**①升级路径与流派构筑 ②特殊状态 / 天赋 ③砖块阵型 ④Boss 战**。优先策划、原型验证和手感评估，不同时铺开四大系统。

### 确认 / 未确认边界

| 状态 | 内容 | 说明 |
|---|---|---|
| **已确定方向** | 单炮台、整波生成、整体下降、清屏推进、清屏后弹球清零、波末三选一升级 | 不回退到普通战斗持续刷砖或多职业初始炮台 |
| **暂定可调数值** | 78块/波、下落速度、耐久增长、Boss HP、波次难度 | 这些是调试参数，仍需真人验证 |
| **已提出但未批准实现** | 最后一块砖自动降为1HP、针对单体Boss的技能、完整流派树、特殊砖状态和阵型主题 | 下一阶段单独讨论并形成可执行规格 |
| **明确排除本轮** | 局外商业系统、支付、广告、签到、持续激光、全新职业、100关生产 | 不是当前核心玩法阶段的任务 |

## 1. 版本轨迹及真实取舍

| 版本 | 主要探索 | 决策 / 经验教训 |
|---|---|---|
| v0.17 | 多球物理、数字砖、连锁技能、巨型球、顺滑破坏反馈 | 仍是**爽感与流畅度的重要对照**；保持真实反弹、持续碰撞 |
| v0.18（classlab） | 四个固定初始炮台职业，尝试激光 | 用户明确不喜欢以四职业取代核心弹球爽感；所谓激光是脉冲而非真正持续激光，**不作为设计基准** |
| v0.19–v0.20 | 单炮台、密集砖阵、持续下降、移动端与音频/性能修复 | 一直补砖虽然保持密度，但过强火力、下降压力和补砖位置容易破坏体验 |
| v0.21 | 前弱后强的阶段成长、耐久增长、8色循环、清屏补砖、Boss预告 | 用户表示**基本满意**；保留初期专注、中期 Build 形成、后期爆发的成长原则 |
| v0.22 | 常驻中场召唤、大规模清屏补砖、局部重叠 | 中途填砖能帮助连击，但重叠导致杂乱、数字难看和不易清理 |
| v0.23 | 禁止重叠，恢复标准尺寸、规范排列 | 解决可读性，但中下层被清空后常出现长距离空跑 |
| v0.24 | 上中下三区桥接召唤、留白庆祝、预告延长 | 解决部分连击断层，但**持续补砖与下降的矛盾仍在**，玩家又被下层召唤砖突然压迫 |
| **v0.25** | **整波密集生成 → 缓慢下落 → 真正清屏 → 下一波**；Boss周期出现 | **玩法基准锁定**：普通波次中途不再刷砖，不等顶部零星砖落下；整波压迫与满屏破坏结合 |
| **v0.26（当前）** | **清完一波=升一级+一次三选一；下落加快；波末清除留场球** | 用户希望继续沿此路线优化，不再更改基础玩法与视觉方向；后续聚焦 Build、状态、阵型、Boss |

**重要否定决策**：不再把「无间断补砖」作为普通波核心；不再把四个永久炮台职业作为主玩法；不恢复堆叠砖；不通过无限阻止清屏来维持爽感。**清屏必须由玩家真正完成，才能得到成就感。**

## 2. 当前 v0.26 玩法规格（已实现，数值可调）

### 2.1 整局与波次

- **一局到底**：从第1波开始，波次逐次增加，Build / 技能等级跨波次持续，生存直到有砖块触及警戒线；不是 10 个互相独立、每关重选职业的关卡。
- **单个起始炮台**：普通弹球真实弹跳、接触砖块扣数字；根据已选技能获得射速、火力、弹速、续航、裂变、电弧、震荡、钻头、追猎、散射、蓄能等变化。**物理弹球始终是体验中心**。
- **普通波次不补砖**：开局一次性生成约78块标准尺寸砖。只有全部砖块真正消灭，才结束该波；不能等待计时自动结束，也不能因只剩几块而自动视为通关。
- **整波下降**：逻辑坐标区域360×560，警戒线约 `y=455`；标准波第1波底部初始约 `y=282`，与警戒线保持约173px；v0.26 下降基准 `6.8 px/s`，随波次小幅提高，普通最高约 `8.4 px/s`；Boss波下降系数约0.9。以上参数是试玩用数值，不是不可改的设计锁。
- **密度与生命值**：9行标准砖，整体较密；底部留3个可反弹通道，包含较多低耐久砖与少量中等耐久砖，颜色按数值范围循环。波次越往后整体耐久逐渐上升，不要全场统一高HP，避免长时间单目标敲击。
- **Boss波**：每第4波（4、8、12……）出现核心Boss；Boss本波可有限召唤辅助砖，总量上限约12；击败核心不意味着本波完成，仍须清掉残砖。

### 2.2 升级与跨波流程

1. 逐块击碎 → 得分 / 获得超载能量 / 打出物理与连锁反馈，**不因为获取经验值而升级**。
2. 全部砖块真正清零（含Boss战收尾） → 该波完成 → 立刻**清除全部普通、裂变、特殊在场球以及巨型球**，不让旧球进入下一波。
3. **等级 +1；仅获得一次三选一技能选择**，选择时游戏暂停。Boss核心被单独击败不再赠送额外升级。
4. 玩家选定后，延续约0.6s清屏庆祝 + 0.9s全场虚线预告，下一波实体砖出现；Build保留、弹球重新发射。
5. HUD 的原「经验条」改为**本波砖块清理进度**；等级只由已完成波次决定。初始LV1，完成第N波后进入LV(N+1)。

### 2.3 现有技能库与开放节奏

| 当前技能 | 角色（现有实现） |
|---|---|
| 射速训练、弹速训练、弹跳续航 | 早期数值基础；不要开局就爆炸强 |
| 火力强化、追猎弯弹、钻头穿阵、蓄能弹跳 | 中期火力、弹道和目标穿透的成长 |
| 散射进化、碎星裂变、电弧印记、震荡核心 | 后期高密度多球、连锁与范围爆发 |

当前代码使用随等级逐步开放技能的门槛（而不是以前按经验/生存秒数发放），并给单项技能设上限。这只是临时**技能池/抽取**，**尚不是完整的 Build 路径、流派、天赋和组合系统**。

### 2.4 已有的技术 / 体验成果

- GitHub Pages 可直接试玩，移动端 iPhone 常见390、375、320视口的单屏布局经过自动浏览器检查，页面无需上下滚动。
- 触控调整炮台、音效首次手势激活、数字砖色盘、撞击粒子/文字、Boss HP条、超载技能等已存在。
- 物理采用固定120Hz步长，绘制采用浏览器 rAF；**不能据此承诺真实设备稳定120 FPS**。已见 iPhone 用户截图显示60 FPS；Headless测试经常只有约30 FPS。
- v0.26 自动测试验证：不中途升级；真正清屏仅升一级；Boss击败无额外升级；波末旧球/巨球清零；选完下一波；移动端布局；60/120Hz模拟计时一致。
- 探索性自动瞄准模拟：v0.26 普通路线约185秒、到第5波、完成4波、击败首个Boss；这只是**自动模拟**，不能替代玩家难度评价。用户反馈 v0.25 第8、12波曾出现仅剩Boss的空场问题。

## 3. 已知问题、真正根因与优先级

| 优先级 | 问题 | 当前判断 | 本阶段处理方向 |
|---|---|---|---|
| P0 | **升级一次/波后，成长选择不够成体系，后期乏味** | 现有是平铺技能池和分阶段解锁，缺乏清晰的路线差异、升级转化与互斥/协同 | 先设计流派图、技能阶段、升级卡概率和成长上限；控制实现范围 |
| P0 | **Boss只剩核心时孤立、单目标敲击乏味** | Boss虽有召唤辅助砖，但召唤有限，配合密集火力会很快只剩核心 | 设计Boss多阶段行为、针对单体Boss的构筑补偿与技能触发，不应靠无限刷辅助砖拖延 |
| P1 | **后期挑战重复** | 只是HP和数量增长，视觉与战术差异不明显 | 设计阵型族、阶段切换、局部弱点和安全球路 |
| P1 | **特殊状态不足** | 只有现有特殊砖/技能反馈，缺少可识别且有意义的状态交互 | 先定义少量规则简单、能强化弹球物理链的状态 |
| P1 | **尾砖很难打中** | 降HP可以减少耗时但无法解决真正的定位/命中问题 | 「最后一块砖自动变为1HP」作为候选技能/天赋；同时评估轻量追猎、弹跳导流等替代设计 |
| P1 | **下落压力与火力不均衡** | 单波成长后更依赖玩家抽到的技能；第4波前经验积累机制已变化 | 真人分别用弱Build/强Build验证失败点，避免无从选择就死 |
| P2 | **手机性能与特效极限** | 大量弹球+裂变+电弧时开销可能高，需实机评估 | 记录 FPS 分布、掉帧来源和发热，不因单次截图推断稳定性 |

## 4. 下一阶段的设计顺序（先策划，分段验证）

### T01｜升级路径与构筑流派（最高优先级）

**目标**：同一炮台、相同的基础波次，因为三选一顺序不同产生明显不同的**破坏方式**，而不是只有「火力数字越来越大」。

交付设计稿至少包含：

- 3个以内可辨认的首批流派候选（例如：**弹幕裂变 / 电弧连锁 / 钻头穿透**）；说明其爽感瞬间、触发链、优势、弱点、Boss单体适应性。
- 现有 11 类技能保留、合并、删减和进阶的边界，避免只是增加技能数量；每次三选一如何构成 build（随机权重、去重、升级上限、解锁波次、先决条件、联动、兜底）。
- `弱 Build vs 合理 Build vs 爆发 Build` 的可达波次区间，以及避免某个核心技能完全不出现导致早死的规则。
- 可验证的指标：第3–5波是否有路线感，第6–10波能否明显爆发，第10波后是否仍有成长目标；**同样不能每局都是一个必胜最优解**。
- 避免把「散射/激光」变成替换所有弹球的独立职业。如果未来研究持续激光，必须是**真正不间断的光束**，且考虑怎样不破坏物理弹球爽感。

**Gate T01**：先形成一页技能路径图 + 关键组合表 + 2–3个可试玩 Build 样例；用户确认再编程。

### T02｜特殊状态与天赋（服务流派，而不是堆功能）

候选方向，仅供设计，不视为已批准：易碎/破甲、导电/感电、标记/追猎、蓄能/爆破、Boss弱点窗口、尾砖降级。逐项明确：谁施加、持续多久、作用于砖还是弹球、如何和其他技能连锁、反馈颜色/特效、性能上限、冲突优先级，以及防止无限伤害循环的规则。

特别讨论「**最后一块变成1HP**」：是否应是专属被动天赋、可选技能等级效果或整局的低强度保底；玩家已倾向把它交给后续流派/天赋系统，不应擅自作为全局自动规则上线。

**Gate T02**：从候选中只选 2–3 个可玩状态，先验证强反馈、可理解、不卡顿。

### T03｜砖块排列阵型（少量可复用阵型族）

**目标**：保持高密度、多次反弹和清屏，但每波在球路和打法上有明显变化。优先设计**可参数化阵型**，不要为每一波手绘完全不同的布局。

建议研究 4–6 个阵型族：环形/中空回弹、交错通道、两翼夹击、集中核心+护卫、分层耐久墙、连锁引爆阵。每种阵型要标注：下层安全距离、砖块总量、密度分布、弹球能否持续多次反射、是否容易只留最上方孤砖、是否阻塞球路、是否会让难度突增。

**Gate T03**：至少3个可对比阵型，自动检测合法无重叠、清屏时间/弹球接触次数/危险线提前触发，真人评估哪种更爽。

### T04｜Boss战重设计（从大血砖变成可构筑的战斗）

**当前问题**：第8、12波截图中，普通砖被快速清完，只剩Boss核心，弹球向四周空转，连击频率下降。不能靠给Boss堆血来提高挑战。

候选机制（待设计）：Boss护卫节拍和打击窗口、阶段变化与破甲、可击中弱点、Boss与阵型联动、技能对单体目标的伤害或触发保底。明确每波辅助召唤总量上限，以免无限召唤阻止清屏。

需要专门评估**三条流派对Boss的公平性**：擅长清群怪的电弧/震荡在仅剩Boss时是否沦为废技能，钻头和追猎是否过强；要让每个流派至少有一种单体战补偿或转化，不是仅靠数值碾压。

**Gate T04**：优先设计一个Boss（第4波）+ 两阶段变化，与3个构筑样例对照；后续再扩展第8/12波Boss，不先造大量Boss美术资源。

## 5. 开发执行规范与验收门禁

1. **先读本文 + v0.26 README / test + 根目录已有约定**，按可确认的最新版实现，不基于早期 v0.17/v0.18 重写规则。
2. 新机制优先在 `compare/hybrid-v27-.../` 独立分支试验，**保留** `compare/hybrid-v25-wave-rush/` 和 `compare/hybrid-v26-wave-level/` 两个对照版本；未获用户确认前不覆盖基准，也不扩展付费系统。
3. **先分析、再规格、后代码**：T01–T04 按顺序单独确认，避免一轮同时引入大量状态、阵型和Boss导致无法判断哪项改善。
4. 每次试玩必须保留手机单屏、首击音效、60Hz/120Hz模拟一致性、合法砖块不重叠、真正清屏/升级一次、下落失败和 Boss 召唤有限这些回归测试。
5. 尽量通过自动化测试模拟强弱 Build，但**自动瞄准模拟数字不是玩家数据**，最终判断以手机真人试玩为准。对每轮记录：存活秒数、通过波数、选择的技能、击碎数、清屏节奏、Boss尾场耗时、掉帧情况。
6. 成功标准不是“拥有更多技能/更多Boss”，而是玩家愿意连续重开、不同 Build 带来不同爽感、普通波与Boss波都能形成持续碰撞，适合后续商业验证。
