## 最新用户决定（高优先级）
1. **手机全屏可用面积明显扩大、右上设置方便、触控瞄准准确**：作为已获用户认可的UI方向保留，后续不要无证据大改。
2. **Boss与小砖发生错位重叠**：用户实际观察到；虽非本轮最大体验阻塞，后续关卡/Boss开发必须修复生成几何，并为不同Boss尺寸做通用防重叠约束。
3. **下降紧迫感不足**，需要查是否为逻辑错误而非盲目加倍率。
4. **普通弹球未明确选择「增加伤害」升级时，每次直接物理命中应扣1点**；不能通过游戏内隐藏/自动增伤把基础球变相变成2伤害。已显式选择的技能可附带其他伤害，但必须用独立的、可辨认的来源和UI解释，不能伪装成基础球直击伤害。
5. **技能卡说明必须更简单、清晰、易懂**。选卡突出单个可理解的本次增量和必要触发规则，真实计算值一致；暂停菜单才展开完整Build和细节。

## 已定位的代码事实（M1.1生产目录）
### A. Boss生成几何冲突（可确证）
- `game.js` `bossSpawn` 固定Boss `x=138,y=108,w=84,h=53`，其覆盖的逻辑Y区间是108–161。
- `createWavePlan` 在Boss波仅排除`row>=2&&row<=4&&col>=3&&col<=5`；但第一行`WAVE_START_Y=84`时，`row=1`砖的Y为112–134，和Boss实体108–161直接相交。此为确定的生成几何Bug，不只是视觉错觉。
- 需要按真实矩形（含间隙）测试所有Boss/砖位，先从Boss区域排除计划砖、同时考虑HUD/topbar动态WAVE_START_Y，再生成有限护卫；加入所有关卡Boss + 宽高尺寸的无重叠几何断言，确保Boss内部和周边无实体叠加。

### B. 手机高度使下降压力变弱（可确证设计缺陷）
- M1.1 `H = clamp(360*innerHeight/innerWidth,560,900)`，危险线`DANGER_Y=H-105`；但初始阵型只随`WAVE_START_Y`调整，固定9行，最下面的砖Y约为`WAVE_START_Y+8*28+22`。
- `generateSurvival` 的下降速度仅 `min(8.4,6.8+(wave-1)*0.09)*bossFactor*fallScale`，与`H`无关。这使长手机上的初始“底砖到危险线距离”明显变大，而移动速度没有按可用距离适配。
- 例如H≈779、WAVE_START_Y=84，第7波底砖到危险线约344逻辑px，非Boss下降≈6.16 px/s，单靠平移约56秒才触线；560高场地同条件仅约20秒。数字仅用于说明设计缺陷，实际阵型/技能会持续变化。
- 修复：用动态场地中的有效危险距离或目标压力窗口来定义下降进度，针对第1/4/7/8/10波、320×568/390×844/430×932、三纯/弱路线分别测试；初期有反应时间、中期有紧迫感但不无解，Boss不靠高HP拖延。**不要只把0.84加到1.0**。

### C. 基础伤害1正确，但存在未经显式选伤害卡的加伤路径（明确来源；用户实际那次需复现）
- `builds.js` `baseDamage:1`；`tuning` 计算`damage=1+(ranks.power||0)`；未升级、未Buff时普通物理直击是1。
- 特殊砖可自动触发`BUFFS.power`：15秒直接伤害+1，`directContact` 中`Build.buffModifiers(build).damage`叠加。因此**不选择增伤升级也会达到2**。
- `directContact` 对孤立Boss每6秒末2秒弱点自动`weak=1`；机枪R2/R3有明示技能来源的连续命中增伤；侧墙蓄势、钻头也能增加选卡后伤害。电弧会在直击后触发独立闪电伤害，同一画面中可能表现为总HP减少超过1；两个真实球同时间分别撞击也可能合计减少2。
- 下一版必须按来源审计、记录`baseHit / selectedUpgrade / temporaryBuff / bossWeak / secondaryArc / physicalSecondBall`。**用户确认的硬约束：未选增伤，不允许普通球的直接命中含隐式+1**。将自动强击Buff替换为非直接伤害Buff或其他经过用户确认的短时能力；Boss弱点不能默认给普通球+1直接伤害，改为显式可见且已获得的攻击机制/命中效率或通过选卡获得。维持“特殊砖只给即时或临时Buff，不给永久资源”。
- 保证`HP=3`基础场景一次独立真实普通球接触必为`3→2`，任何`3→1`要有**两个独立物理命中**或**玩家明确选取的额外伤害效果**，并可在浮字/战斗日志中区分。Boss、小球、群伤、双球、Buff和升级均应有独立断言。

### D. 技能说明过于工程化
- 当前选卡由`builds.js` `card()` 拼接`deltas`，如`传播位`、`R2`、`同屏预算`、`未用传播位聚能`、`真实子球`等仍难理解。
- 改为**技能名称 + 本次增加多少 + 一句触发条件/实际玩法**。不要同时列三四项工程参数。描述使用明确单位：射速`+10%`（按计算得实际值）、分裂`+1颗`、闪电`+1目标`、追猎`+1次`。新增能力用“获得新能力：……”，互斥选择用短句提示。暂停详情可显示全部机制/真实累计数值。
- 进化分支必须说清楚是否替换、是否互斥；同名机制与原技能有何区别。不得把示意+10%硬编码成不真实的效果。
