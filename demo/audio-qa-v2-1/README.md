## 一、四类实际音效事件

球击中砖块只有两种互斥结果，另加两个全局节点。

| 音效事件 | 可选内容 | 文件 |
|---|---|---|
| 砖甲受击（击中但砖块存活） | V5 木质轻敲 / V5 木板闷响 / 无音效 | `demo/audio-qa/audio/mg.ogg`、`hit.ogg` |
| 砖块击破（HP 归零、实际摧毁） | break-x11 · impactGlass heavy 000 / 无音效 | `audio/break-x11-impactGlass_heavy_000.ogg` |
| 清屏升级（清屏与升级同一节点） | **A 原版 3.44s / B 短版 1.35s / C 中短版 1.80s / 无音效** | `audio/clear-x14-Upper01*.wav` |
| 触线失败 | fail-02 · 02 错误提示中音 / 无音效 | `audio/fail-02-error_005.ogg` |

**击破不是第三种声音，而是同一次碰撞的第二种结果。** `hitBrick()` 里
`if(b.hp>0){...playSfx("armor");return false;}` 保证砖块存活时提前返回、走不到击破分支；
被击穿时直接走到底部的 `playSfx("break")`。二者不可能在同一次碰撞里都触发。

## 二、Upper01 A/B/C

三段是**同一段波形**，只改裁剪长度与尾部淡出，不变速、不变调、不重编码音色。

| 版本 | 文件 | 时长 | 淡出 |
|---|---|---|---|
| A 原版 | `audio/clear-x14-Upper01.wav` | 3.436553s | 原始自带 |
| B 短版 | `audio/clear-x14-Upper01-short-1.35s.wav` | 1.350000s | 1.15s 起，200ms raised-cosine |
| C 中短版 | `audio/clear-x14-Upper01-short-1.80s.wav` | 1.800000s | 1.55s 起，250ms raised-cosine |

三段均为 44100Hz / 16bit / 立体声 / PCM，峰值相同（-5.51 dBFS），无削波。
**A 原文件未被覆盖**（MD5 不变），B/C 是新增文件。

波形分析结论（见交付报告）：主峰在 0.90s，之后是持续衰减的释放段；2.21–2.40s 有 190ms 的 -47dB 间隙，
2.42s 到结尾 1.02 秒基本是 -45 → -74dB 的静音尾。所以 B/C 并不损失任何独立乐句，差别只在释放段长度；
原版后 1 秒其实是听不见的静音，却让下一次清屏要等更久。

## 三、原合成提示音本轮默认关闭（可一键恢复）

`game.js` 顶部有一个开关：

```js
const LEGACY_SYNTH_CUES_ENABLED = false; // 改 true 即整体恢复
```

关闭的是 `playSfx()` 里由 `beep()` 生成振荡器的五个提示音：`split`（裂变）、`hunt`（追击）、
`drill`（钻头）、`arc`（电弧）、`giant`（超载冲锋 **与 Boss 降临共用**）。

- 只关播放，`beep()` 函数、五个 `playSfx("…")` 触发点全部保留，改回 `true` 即恢复，无需其它改动。
- **不会**误关四类素材音效：开关在 `PinballGameAudio.play()` 与合成音白名单之后才生效。
- 不影响 `tapHaptic()` 振动反馈。
- 审计结论：全工程只有 `playSfx → beep` 一个合成音入口；`juice-fx.js`、`builds.js`、页面均无 `<audio>` 或第二个 `AudioContext`。
- **README 旧版写的「Boss 预警」不是一个独立事件**，它就是 `bossSpawn()` 里复用的 `playSfx("giant")`，与超载冲锋同一个 beep。

## 九、V2.1h：连续击破的"杂音"修复（2026-11-10）

用户反馈：砖块击破音一旦多起来，会变成"咋一下"的爆破杂音。

**根因不是素材，是播放策略。** 原来 `cut()` 直接 `source.stop()` 硬切，而 `brick_break`
是 `cooldown 46ms / maxVoices 2`——0.16s 的样本在 46ms 间隔下最多要 3.5 层，被卡在 2 层，
于是**每来一次新击破就硬切一次旧的**。实测 24 次连续击破触发 **22 次硬切**，每秒二十几个断点，
听感就是"咋咋"的杂音。

四处修复：

| 位置 | 改动 |
|---|---|
| `cut()` | 12ms 余弦淡出后再 `stop`，不再硬切（断点消失） |
| `emit()` | 每条样本 ±6% 随机变调，避免同一条反复触发时相位对齐 |
| `emit()` | 叠音衰减 `1/(1+0.5×已响层数)`：2 层 -33%、3 层 -50% |
| `emit()` | 叠音高通：已在响时新来的那条切掉 180–900Hz 低频，只贡献瞬态，防止低频叠成轰鸣 |
| `brick_break` | `cooldown 46→62ms`、`maxVoices 2→3` |

实测对比（24 次连续击破）：

| 参数 | 硬切次数 |
|---|---|
| 旧 46ms / 2 层 | **22 次** |
| 新 62ms / 3 层 | **0 次** |

素材本身的谱平坦度（越高越像噪声）：`break-brick-e-neutral` 0.0063、`break-brick-d-deep` 0.0011、
旧 `impactGlass_heavy_000` ≈0。都不是噪声型素材，所以没有换源的必要。

## 十、V2.1i：去掉击破音的低频层（2026-11-10 09:20）

V2.1h 修完硬切后用户仍反馈"只要声音一多，还是会有爆破声"。测分频段能量后定位到素材：

| 素材 | 150Hz 以下能量 |
|---|---|
| `impactMining_002`（上一版的"石块本体"层） | **78%** |
| `break-brick-e-neutral`（合成成品） | **51%** |
| `break-brick-d-deep`（合成成品） | **75%** |
| `impactWood_light_000` | 4% |

也就是说上一版的击破音有一半以上能量是 60–110Hz 的闷轰。单条听着像"石块落地"，
一旦两层以上叠加就变成低频轰鸣——这就是"爆破声"。引擎再怎么调，素材里塞了 80Hz 的爆轰是调不掉的。

改动：

- 击破候选取掉 `impactMining` 层，换成纯中频：`BREAK-M1`（wood light 000 单层，150Hz 以下 **1%**）、
  `BREAK-M2`（wood light 002 + generic light 001，**4%**），0.11s / 0.10s
- 事件表新增 `hp` 字段，`brick_break` 设为 **200Hz 静态高通**：以后即使换回低频素材，
  这一路也会先切掉低频，不会再叠出爆破声
- 叠加时在高通基础上再抬拐点（180 + 120×层数，上限 900Hz）

实测 8 次连破：8 条都是 0.11s，高通拐点依次 200 / 300 / 300 …，0 控制台错误。

## 十一、V2.1j：击破/撞墙的"爆破声"真因——波形未从零点开始（2026-11-10 09:30）

用户对比后给了关键线索：**砖甲受击不炸，击破和撞墙炸**。

先排除电平：实测总线峰值 0.53 / 0.12 / 0.12 / 0.08，没有任何削波（`over = 0`），
且撞墙与砖甲受击电平几乎相同（0.123 vs 0.122），所以不是音量问题。

再查波形起始，找到真因：

| 文件 | 首样本值 | 结果 |
|---|---|---|
| `break-mid-wood.wav` | **-0.703** | 每次播放都是一次 0.7 的垂直台阶 |
| `wall-bounce-wood-light-000.wav` | **-0.152** | 0.15 的台阶 |
| `hit.ogg`（砖甲受击，Kenney 原文件） | -0.057 | 可忽略 |

这些文件是从素材中段直接切的，波形没有从零点开始；再做峰值归一化（0.89）时，
这个起始台阶被**放大了 4.6 倍**。每次播放等于先"啪"一下，连破时就是密集的爆破声。

修复：

- 五个文件全部做**零点对齐**（找第一个过零点，平均裁掉 0.1–1.5ms）+ **1.5ms 淡入**
- 修复后首样本全部为 0.000
- 击破增益 `.62 → .45`（归一化修正后它比砖甲受击响 3.6 倍，压到 2.7 倍）

实测总线峰值：击破 0.416 → **0.310**，撞墙 0.089，砖甲受击 0.117，清屏 0.076，全部无削波。

### 教训

生成音频时，**裁剪必须从过零点开始并加短淡入**；否则峰值归一化会把起始台阶放大成爆音。
这个问题在单次试听时几乎听不出来（就是一下"啪"），只有连续触发才暴露。
